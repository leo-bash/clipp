# Pipeline

The intended pipeline is candidate → analysis → plan → TTS → render → QC → review → schedule → publish → analytics → cleanup. Queue names and worker boundaries are explicit: discovery, ingestion, transcription, analysis, planning, tts, render, qc, review, publish, analytics and cleanup. The dedicated TTS consumer uses the deterministic cached adapter in local mode, can use the official ElevenLabs adapter when runtime credentials are configured, reserves the estimated cost before synthesis, and defers when no configured provider is available. It never calls a paid provider implicitly. Permanent application errors are not retried by BullMQ and are retained in the queue dead-letter flow.
